## Agreed Approach

Layer 2 customization: one-time generation that derives paces from a baseline
time trial and writes ordinary plan data (track `guidance`), plus a durable
customization-run record so the origin is auditable. Hermetic derivation module
under `Improve.Planning.*`; `App.customize_plan!` orchestrates; Ash actions
persist. Backend-only, story-first, no UI.

## Summary of Changes

Layer 2 baseline customization is implemented: one-time generation that derives
training paces from a baseline time trial, bakes them into track `guidance` as
ordinary plan data, and records a durable customization run. Customization is
clearly separate from projection-time adaptation (Layer 3): it writes once via
Ash actions; projection only ever reads the result.

Backend-only, story-first, no UI.

### Model
- `Improve.Plans.Track`: added optional generic `guidance` map (`lib/improve/plans/track.ex`).
- `Improve.Plans.Customization`: new plan-scoped resource recording a customization run (key, kind, self-contained baseline snapshot, recipe, outputs, applied_changes) (`lib/improve/plans/customization.ex`).
- Registered Track `:update` and Customization create/update/get/list code interfaces on `Improve.Plans`.

### Hermetic derivation
- `Improve.Planning.Customization.derive/2`: pure baseline payload + recipe -> named pace outputs, with plain-English diagnostics (`lib/improve/planning/customization.ex`).

### Orchestration
- `Improve.App.Customize.customize_plan!/2`: resolves the latest active baseline event, derives outputs, applies guidance to the named tracks via Track update, and persists a customization record (update-or-create so re-customizing is idempotent) (`lib/improve/app/customize.ex`).
- Wired `App.customize_plan!/2` and `Story.customize_plan!/show_customization!`.

### Story
- `priv/scripts/stories/10_adaptive_marathon.exs` Layer 2 now runs: derives easy/marathon/tempo/interval paces from the 25:00 5k baseline, applies them to the four run tracks, and shows the customization record. Layer 3 (adaptation) remains fenced as INTENDED.
- Added `customizations` to the story reset cleanup.

### Tests
- Unit tests for the derivation module (6).
- App integration tests: derive+write+record, idempotent re-customize, missing-baseline diagnostic (3).
- Story helper test for customize + show_customization (1).

### Migrations
- `20260624224936_add_track_guidance_and_customizations.exs` (autogenerated) + snapshots.

Verification:
- `mise run verify:backend` green (fmt, compile --warnings-as-errors, 153 tests, ash_typescript.codegen --check, tsc, all stories).

### Notes / deferred
- Paces are track `guidance`, not target data; projection does not yet surface guidance in projected_work payload or show_projection output (kept out of scope; customization layer proven via the auditable record + baked guidance).
- Recipe is marathon/pace-specific (`{:secs_per_km, field, plus|minus: n}`); a generic derivation framework is intentionally deferred until a second customization kind forces it.
- No Phoenix/TypeScript RPC surface for customization yet (kept representative, consistent with TimeOffWindow).
