# Plain-English Spec: Initial Svelte Frontend App

## Goal

Create the first frontend app for Improve.

This should be a plain Svelte + TypeScript + Vite app.

It should live in the same repo as the Elixir backend, but it should be isolated in its own directory.

This first step should not include auth, product features, routing, API integration, styling systems, component libraries, AshTypescript, or anything clever.

The goal is simply to create a standard frontend app that boots, builds, and is easy for humans and AI agents to understand.

## Non-goals

Do not add auth yet.

Do not add signup/login screens yet.

Do not add product screens yet.

Do not add SvelteKit.

Do not add a router yet.

Do not add Tailwind yet.

Do not add Bits UI or shadcn-svelte yet.

Do not add TanStack Query.

Do not add AshTypescript yet.

Do not add Phoenix or API wiring yet.

Do not add custom build tooling unless the scaffold requires it.

This is just the frontend skeleton.

## Directory

Create the app under:

```text id="ynlv9u"
frontend/
```

The repo should end up looking roughly like:

```text id="x8frj0"
improve/
  lib/
  config/
  priv/
  test/
  mix.exs

  frontend/
    index.html
    package.json
    vite.config.ts
    tsconfig.json
    src/
      App.svelte
      main.ts
      app.css
```

The frontend should be replaceable. Nothing in the backend should depend on Svelte internals.

## Scaffold command

Use the latest Vite scaffold.

Recommended command:

```bash id="73e3sd"
npm create vite@latest frontend -- --template svelte-ts
```

Then:

```bash id="5qk3io"
cd frontend
npm install
npm run dev
```

The app should start locally and show the default Svelte/Vite screen.

## Package manager

Use `npm` for now.

Do not introduce pnpm, yarn, bun, workspaces, or monorepo tooling yet unless the repo already uses them.

The boring default is good here.

## Initial scripts

Keep the standard scripts generated by Vite.

The `frontend/package.json` should have scripts like:

```json id="cl3u2j"
{
  "scripts": {
    "dev": "vite",
    "build": "vite build",
    "preview": "vite preview",
    "check": "svelte-check --tsconfig ./tsconfig.json"
  }
}
```

The exact generated scripts may vary slightly. Do not over-customise them yet.

## First app content

Replace the default demo content with a very small Improve placeholder.

Example:

```svelte id="q67dgy"
<script lang="ts">
  const appName = "Improve";
</script>

<main>
  <h1>{appName}</h1>
  <p>The frontend app is running.</p>
</main>
```

Keep it intentionally boring.

This should prove:

```text id="url8pa"
Svelte compiles.
TypeScript works.
Vite dev server works.
The app can be built.
```

## First checks

From inside `frontend/`, run:

```bash id="msergs"
npm run dev
```

Then separately run:

```bash id="5tp4le"
npm run build
```

If the generated project includes a check script, run:

```bash id="7beoek"
npm run check
```

The initial milestone is complete when:

```text id="zbc0o4"
The dev server starts.
The browser shows the Improve placeholder.
The production build succeeds.
Type checking succeeds if a check script exists.
```

## Git expectations

Commit the scaffold as its own small commit.

Suggested commit message:

```text id="lheqae"
Add initial Svelte frontend scaffold
```

This keeps the frontend foundation separate from later choices like styling, routing, auth, and API integration.

## What comes after this

After the scaffold is committed, later steps can add things one at a time:

```text id="a7lwwd"
1. Basic app shell
2. Simple styling
3. Bits UI or other component primitives
4. AshTypescript client generation
5. First backend health/API call
6. Today placeholder screen
7. Email-code auth flow
8. Real product screens
```

Do not add those in the initial scaffold commit.

## Main decision

Use the latest Vite scaffold with the Svelte TypeScript template.

Keep the app standard.

Keep it isolated.

Keep the first commit boring.
